TrainerAdapter PLUGGABLE
Docker container — VERL FSDP · 8×A100
Pure consumer. Calls get_batch from LiveStore, pads groups to tensors, computes GRPO advantages, runs FSDP actor update, saves checkpoint, publishes LoRA to PolicyRegistry. No parquet, no ProRL URL, no vLLM URL.
BC-15 LiveStore + Registry only BC-9 abort on publish fail

Training cycle: parquet → RolloutManager → ProRL+vLLM → LiveStore → TrainerAdapter → PolicyRegistry → vLLM (LoRA reload) → RolloutManager (manifest poll)
Services are independently replaceable — swap the trainer or environment by implementing the typed Protocol contract.

Boundary Conditions

ID Rule What breaks if violated
BC-0 One PolicyVersionSnapshot per group — all siblings stamped before dispatch Siblings see different policies → invalid advantages, NaN loss
BC-1 Token IDs as int on every wire — never decode and re-tokenize Token boundary shift → actor/reference diverge → KL/entropy NaN within 2 steps
BC-9 endpoints_failed > 0 is a hard abort, never a degraded mode Mixed-version vLLM pool → importance-sampling weights become lies, silent gradient corruption
BC-13 RolloutManager imports zero VERL / OpenHands code Swapping trainer requires rewriting the worker
BC-14 RolloutManager owns the parquet dataloader — trainer has no data.train_files Trainer becomes a hidden orchestrator; pluggability breaks
BC-15 Trainer connects only to LiveStore + PolicyRegistry Swapping VERL for another trainer requires more than a Docker image swap
BC-16 Start trainer only after ≥1 group in LiveStore 30-min no-progress timer burns during warm-up; trainer starves immediately
