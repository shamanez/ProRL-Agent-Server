ProRL Redesign: Async RL + Replay + Iterative Off-Policy

Core idea: keep ProRL as the rollout service, but make policy publishing, serving cutover, replay, and training mode selection first-class. The system supports two modes: continuous async replay and large-batch iterative off-policy training.

Why change

  • Step-perfect weight sync is too expensive and fragile.
  • External vLLM workers need a real publish / warm / activate / drain workflow.
  • Agentic multi-turn rollouts need masking and segment-aware training.

Mode A: Async replay

  • Inference workers continuously generate rollouts.
  • Trainers sample from replay buffer.
  • Weights publish every N steps or every T minutes.

Mode B: Iterative off-policy

  • Freeze a reference policy version.
  • Generate a large dataset offline.
  • Train many updates on that dataset before next publish.

Invariant 2
No trajectory changes serving version mid-run.
Invariant 3
Replay is bounded by explicit freshness rules.
Invariant 4
Serving and training can evolve independently.

Phase 1: single-developer starting plan

1Keep ProRL rollout server unchanged.

2Replace trainer-owned hybrid vLLM spawning with external endpoint registration.

3Add policy registry metadata and blue-green cutover.

4Implement iterative off-policy mode first for easiest weight sync.

5Add bounded replay buffer once external serving is stable.

What to monitor

  • W/T ratio (inference workers vs trainers)
  • buffer size N
  • average staleness / off-policiness horizon
  • replay ratio
  • steps-since-last-use
  • policy version lag and drain backlog
This plan intentionally separates rollout orchestration, serving lifecycle, replay / offline dataset handling, and training objectives so that multiple trainers can share the same rollout substrate without inheriting one trainer's runtime assumptions.
