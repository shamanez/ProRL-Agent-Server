Repo name: RolloutFabric

RolloutFabric

Agentic RL training fabric that separates rollout generation, sandbox execution, hot storage, training, inference, and policy publishing into swappable service boundaries.

Rollouts are outside the trainer The RolloutManager owns parquet data, group dispatch, and sample construction.
Training reads one service The trainer pulls unpadded samples from LiveStore and pads locally.
Token handling stays in ProRL ProRL/OpenHands tokenizes chat history, detokenizes model IDs for tool calls, and returns token IDs.

Service Boxes

RolloutManager

Turns parquet rows into policy-stamped training groups.

ParquetDataLoader PolicyVersionCache ProRLClient EpisodeBuilder LiveStoreClient.push_group

EnvironmentProvider

Runs the SWE-Bench/OpenHands tool loop and owns tokenizer-side text/token conversion.

POST /process Qwen tokenizer Chat to prompt_ids response_ids to tool text Singularity Reward result

InferenceBackend

Serves token generation and hot-reloaded LoRA adapters.

vLLM children /vN/generate /reload_lora LoRA LRU

LiveStore

Decouples rollout speed from trainer step speed.

Bounded FIFO PushGroup GetBatch Pop-on-sample Staleness eviction

TrainerAdapter

Consumes groups, pads locally, runs FSDP, publishes adapters.

LiveStoreClient pack_unpadded_groups GRPO/DAPO PolicyRegistryClient

PolicyRegistry

Owns policy version truth and vLLM reload fanout.

PublishPolicyVersion SQLite history Manifest write Abort gate

Rules That Define the Boundaries

BC-0 One PolicyVersionSnapshot per rollout group.
BC-1 Token IDs stay integers on every wire.
BC-9 Any failed LoRA reload is a hard publish failure.
BC-13 / BC-14 RolloutManager has no VERL/OpenHands imports and owns the dataloader.
BC-15 Trainer connects only to LiveStore and PolicyRegistry.

Startup Order

1. vLLM poolRemote InferenceBackend on ports 8100-8103.
2. ProRLEnvironmentProvider on port 8006.
3. LiveStoreUnix socket buffer for rollout groups.
4. PolicyRegistryVersion DB and LoRA fanout service.
5. RolloutManagerStarts filling LiveStore from parquet tasks.
6. TrainerStarts after at least one group is available.
